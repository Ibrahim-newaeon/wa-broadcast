    Get your broadcasts live

    A hands-on walkthrough of the WhatsApp Broadcast Console — from first boot to recurring campaigns. Tick items off as you go; your progress is saved in this browser.

    1 What you're building

    A self-hosted console that sends approved WhatsApp template messages to lists of contacts over Meta's Cloud API, tracks delivery in real time, and honors opt-outs automatically.

    Cloud APITemplate broadcastsLive delivery tracking Scheduling + dripOpt-out complianceTeam accounts
    Three processes run together: the web app, a worker (sends + recurring scheduler), and Postgres + Redis. Docker Compose wires them up.

    2 First boot

    Pick how you want to run it.

    # 1. configure
cp .env.example .env
# 2. hash your admin password → paste into ADMIN_PASSWORD_HASH
node scripts/hash-password.mjs 'YourStrongPassword'
# 3. boot everything (runs migrations automatically)
docker compose up --build

    App → http://localhost:3000 · Health → /api/health

    npm install
npm run prisma:migrate -- --name init   # applies migrations
node scripts/seed-admin.mjs              # creates the first ADMIN
npm run dev        # web :3000
npm run worker:dev # worker (second terminal)

    3 Connect WhatsApp

    From the Meta App dashboard you need four values in your .env:

    VariableWhere
    WA_PHONE_NUMBER_IDWhatsApp → API setup
    WA_BUSINESS_ACCOUNT_IDWhatsApp → API setup
    WA_ACCESS_TOKENSystem-user permanent token
    META_APP_SECRETApp → Settings → Basic

    Webhook

    In WhatsApp → Configuration, set the callback URL and verify token, then subscribe to messages:

    Callback URL:  https://YOUR_DOMAIN/api/webhooks/whatsapp
Verify token:  (value of WA_WEBHOOK_VERIFY_TOKEN)
    Testing locally? Tunnel with ngrok http 3000 and use the HTTPS URL. Every webhook is HMAC-verified against META_APP_SECRET.

    4 Sync templates

    You can only broadcast templates Meta has approved. Pull them into the console:

    GET /api/templates?sync=1

    Approved templates then appear in the broadcast and campaign pickers. Each {{1}}, {{2}} placeholder becomes a variable you map per-contact.

    5 Upload contacts

    On Contacts (or the dashboard upload card), import a CSV. A phone column is required; name is reserved; any other column becomes a template variable.

    phone,name,city
+966 50 000 0001,Ahmed,Riyadh
965 5000 0003,Fahad,Kuwait City
    • Phones are normalized to E.164 digits; bad rows are rejected and counted.
    • Optionally attach the upload to a list — broadcasts target lists.
    • Manage everyone on the Contacts page: search, opt out / re-subscribe, delete.

    6 Send a broadcast

    Dashboard → New broadcast: pick a template + list, fill the variables, send now or schedule.

    How variable mapping works
    Each variable input is either literal text (used for everyone) or field:name / field:city to pull each contact's value. Order matches {{1}}, {{2}}, ….
    Scheduling
    Set a future date/time to schedule — the broadcast shows SCHEDULED until it fires, then flips to SENDING. Leave it blank to send immediately.
    Opt-outs are filtered before anything is queued, and the worker throttles to WA_MPS (default 80/s) so you never exceed Meta's tier.

    7 Monitor & retry

    Click a broadcast to open its detail page. While it's in flight you'll see a ● live progress bar that polls every few seconds.

    • Filter recipients by status (PENDING / SENT / DELIVERED / READ / FAILED) and load more.
    • If any failed, hit Retry N failed — it re-queues just those with the saved variables.
    • Inbound STOP auto-opts-out a contact from all future sends.

    8 Recurring / drip campaigns

    On Campaigns, create a schedule that fires a fresh broadcast on a cron (UTC). Pick a preset or write your own.

    CronMeaning
    0 9 * * *Every day 09:00 UTC
    0 9 * * 1-5Weekdays 09:00 UTC
    0 9 1 * *1st of each month 09:00 UTC

    Pause/resume or delete any campaign at any time. Each run honors opt-outs and the rate limit just like a manual send.

    9 Team & security

    • Settings → invite teammates (ADMIN or MEMBER). Only ADMINs can manage users.
    • Sessions use short access tokens + rotating refresh tokens — Sign out everywhere kills every session.
    • Login is rate-limited; all data and APIs sit behind auth except the webhook and health check.
    Never expose the console publicly without HTTPS. Contact phone numbers are PII — keep your database volume encrypted at rest.
