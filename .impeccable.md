## Design Context

> Source of truth for all design work in this repo. The applied design system lives in
> `src/app/globals.css` (documented in `theme/THEME.md`, `theme/design-tokens.json`). This
> file captures the *who/why/feel* that code can't express. Brand lineage: **NazzilVideo**.

### Users
The Broadcast Console is multi-tenant and serves a **mixed audience**:
- **Agency operators** — power users running WhatsApp campaigns across many client businesses,
  switching tenants, working at a desk, doing the same flows repeatedly.
- **Less-technical client users** — business owners/managers sending to their own customer
  list, who need guardrails and clarity, not raw power.

The interface must serve both without dumbing down for one or overwhelming the other:
progressive disclosure (simple defaults up front, power features one layer deeper).
Jobs to be done: upload contacts → send approved template messages to lists → watch delivery
in real time → honor opt-outs → reply two-way in a live inbox.

### Brand Personality
**Polished & premium.** It should feel like a paid SaaS product worth the price — refined,
unmistakably branded, with delight in key moments (a clean send confirmation, a live progress
bar filling, a campaign completing). Operators should feel **confident and in control** even
during high-volume sends; nothing should read as alarming or janky. Three words:
**refined · trustworthy · alive.**

Emotional goal: the quiet confidence of a well-run command center — real-time status you can
trust, no surprises, every interaction feeling fast and intentional.

### Aesthetic Direction
**Evolve the established system — don't replace it.** Keep the NazzilVideo DNA (dark base,
teal→green signature gradient, orange highlight, Inter/Cairo, the two-tone wordmark) but push
it further: stronger type hierarchy, bolder and more asymmetric layouts, signature branded
moments, more deliberate motion. Update `globals.css` tokens when an evolution warrants it
rather than inventing parallel systems.

- **Theme:** dark by default (the app is a focused operator surface used in long sessions);
  the existing `[data-theme="light"]` opt-in stays supported. Marketing/landing/login surfaces
  may go **bolder and more expressive** than the disciplined app UI.
- **Palette:** the existing OKLCH-able token set — surfaces `--bg/--card/--line`, accents
  `--teal` (primary) / `--green` (success) / `--orange` (highlight) / `--danger`, and the
  per-status delivery colors. Tint neutrals toward the teal hue. Reserve accents for rare,
  meaningful emphasis (60-30-10 by visual weight).
- **Type:** Inter (Latin body) + Cairo (Arabic), with Schibsted Grotesk as the display face on
  marketing surfaces. Keep clear hierarchy (≥1.25 ratio steps). Cap body line length ~65-75ch.

**Anti-references:**
- Do **not** look like WhatsApp itself, or like generic competitor tools (WATI / Infobip).
  This is its own premium brand, not a clone.
- Avoid generic AI-dashboard tells: cyan-on-dark neon, purple→blue gradients, gradient text,
  colored side-stripe borders on cards/alerts, identical icon-topped card grids, hero-metric
  templates, everything-in-a-card, everything centered.

### Design Principles
1. **Evolve, don't fork.** Build on `globals.css` tokens and the NazzilVideo brand; promote
   improvements into the shared system instead of one-off styles.
2. **Two audiences, one surface.** Progressive disclosure — simple and reassuring on top,
   powerful underneath. Never amputate functionality on mobile; adapt it.
3. **Trust through real-time clarity.** Delivery status, progress, and opt-out state must read
   instantly and calmly. Status color is meaningful, never decorative.
4. **Premium in the details.** Spacing rhythm, type contrast, focus states, and one
   well-orchestrated motion moment per view — not scattered micro-animations.
5. **Bilingual & fast by default.** Every change preserves EN/AR + RTL (logical properties,
   Cairo switch) and respects a tight performance budget — no heavy assets or bloated motion.
